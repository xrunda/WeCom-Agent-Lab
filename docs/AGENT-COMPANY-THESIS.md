# 从「人盯群」到 Agent 公司：知伴的产品世界观与经营论

> **定位**：本文是产品世界观、经营论与对外沟通底稿，不是需求文档、验收依据或路线图承诺。
> **状态**：2026-11-10 整理。事实边界以文末「别说过头的边界」为准。
> **用法**：对外沟通时可取其中段落；对内开发时，具体范围仍以 [PRD.md](../PRD.md)、[docs/P1-scope.md](./P1-scope.md) 和工作包 issue 为准。

---

把前面“人盯人、人盯群”的判断，和 Kavak 这几条放在一起，真正的论点其实只有一个：

> **AI 的规模效应，不是复制劳动力，是复制判断。当判断可以被复制，公司的增长函数就变了。**

下面按这个逻辑重新整理，重点放在第三到第六个变化，以及它们如何落到这套知伴系统上。

---

## 一、先看旧模式为什么必然到顶

传统健康管理公司的产能公式是：

**产能 = 顾问人数 × 注意力 × 主管的抽检覆盖率**

它有三个死结：

1. **增长靠加人。** 多一个群就多一份注意力，增长线性；顾问离职，客户关系和经验一起被带走。
2. **质量靠肉眼。** 主管只能抽检，无法全量；等投诉发生，才知道哪条消息出了问题。
3. **经验锁在个人脑子里。** 销冠的方法复制不了，新人培养慢，同一个机构服务口径不一致。

所以旧模式的天花板不是市场，是**人**。

---

## 二、第三个变化最狠：AI 复制的不是普通员工，是最优秀的员工

Kavak 一开始就没想做一个“够用的 Agent”，而是要做 **Superhuman Agent**——在关键指标上超过历史上最优秀的人。

这件事第一次可能成立，是因为最优秀的销售也会累、会忘、会情绪不好；他不可能记住几百万个客户，不可能同时是汽车专家、贷款专家、保险专家、金融专家。但 Agent 可以：无限耐心、记得所有历史、永不疲劳、同时拥有十几个专家的知识。

更关键的是：**一个人的经验只属于一个人；一个 Agent 犯了一次错，第二天所有 Agent 可以同时学会。**

所以：

- 工业革命复制的是**肌肉**；
- 软件复制的是**流程**；
- Agent 开始复制的是**判断和经验**。

落到这套知伴系统上，机制是对得上的：

| Kavak 的机制 | 知伴系统里对应的东西 |
|---|---|
| 不追求“够用”，追求超过最优秀的人 | 不追求“能回就行”，追求顶尖顾问水平的草稿 + 健康红线 + 可核验 |
| 无限记忆、多专家知识 | 每个客户一份长期记忆；健康知识、风险规则、话术、技能都在 Agent 侧 |
| 经验复制 | 顾问的改稿、升级、处理告警、最终发送，全部被记录成可复用数据 |
| 一个人犯错，所有 Agent 学会 | 一次纠偏沉淀为知识/规则/话术，经沙盒和评测后同步到所有群 |

这里最值钱的不是“Agent 会写回复”，而是**它知道什么才算好回复**。在健康管理里，最优秀顾问的判断往往不是“说得多专业”，而是：

- 什么时候该追问，什么时候不该追问；
- 什么话能说，什么话必须留给医生；
- 哪个客户该升级给主管，哪个客户只需要一句安抚；
- 哪条消息发出去会出事。

这套系统把上述判断变成了可回读、可核验、可复用的数据：**原样采纳、改后发送、发错群、未核验**。这四类结果，就是“最优秀员工”的训练信号。

> 这就是谈价时最硬的一句话：**竞品可以复制你的模型和界面，但复制不了你已经跑出来的纠偏数据和客户群历史。**

但要说清楚：医疗健康不是二手车交易，**不能也不应该全自动发群**。这里的 Superhuman 不是“Agent 自己决定一切”，而是“顶尖顾问水平的判断 + 红线 + 证据链 + 人在信任边界上确认”。这反而比“全自动”更值钱，因为它可追责。

## 三、第四个变化：不是人调用 AI，是 Agent 调用人

过去大家讲 Human in the Loop：AI 不行了转人工，听起来人是最后的老板。但 Kavak 发现这个设计有个大问题：**Agent 把问题扔给人工以后，它就失去这个任务了，学习闭环断了。**

所以他们反过来设计：Agent 遇到解决不了的问题，不是退出，而是调用一个 API——“I need help.” 这个 API 的另一边不一定是软件，可能是一个人。

也就是说：

> **Agent 仍然是任务 Owner，人类只是它调用的一种能力。**

这套系统的架构，本质上就是这个方向：

| 旧 Human-in-the-loop | 知伴的做法 |
|---|---|
| AI 不行了就转人工，任务 Owner 变成人 | Agent 始终拥有“这条草稿”的任务；人只在不可逆的发送、临床判断、关系修复节点被调用 |
| 转人工后，学习闭环断裂 | 人的确认、改稿、发错群都会被回读核验，重新进入学习闭环 |
| 人是驾驶员，AI 是副驾驶 | 谁最适合完成这一段，谁就是工具；有时 AI 是人的工具，有时人是 AI 的工具 |

所以未来一个健康管理公司的岗位会分成三类：

1. **Build Agents**：造 Agent、写知识、定规则、做评测、跑沙盒；
2. **Work for Agents**：确稿、纠偏、处理例外、修复关系；
3. **留在 Physical World**：面诊、线下服务、真实信任，这些 AI 暂时替代不了。

这就是“人为 Agent 打工”的准确含义：不是人没有价值，而是**价值杠杆从“人的工时”转移到了“Agent 的覆盖率与学习速度”**。公司雇人，不再是为了让人多干活，而是为了让人补 Agent 的短板、承担 Agent 不能承担的责任。

## 四、第五个变化：Evals 不是测试部门，是管理系统

“想踩油门，你得先有刹车。”

企业为什么不敢让 Agent 真正干活？很多时候不是 AI 不够聪明，而是**你不知道它到底干得好不好**。

Kavak 在 Evals 上投入的资源几乎和做 Agent 本身一样多，而且他们不看“打了多少电话、回复了多少消息、节省了多少分钟”这种漂亮但没用的指标。他们看的是：车卖出去了吗？贷款批下来了吗？客户回来了吗？利润提高了吗？

一句话：

> **不要考核 AI 有多忙，要考核 AI 创造了什么结果。**

这套知伴控制台，本质上就是“AI 员工的管理系统”，而不是一个聊天后台。它现在能看的是：

- 草稿采纳率；
- 核验通过率；
- 平均响应时长；
- 未核验、发错群、超时升级；
- 主动关怀、客户活跃、顾问人均服务群数。

这些是“服务质量”指标。下一步要接的是“经营结果”指标：客户留存、续费、投诉率、单群服务成本、顾问人均产出。

管理 AI 员工的核心，也不再是 Prompt，而是 **Goal、Evolve、Feedback**——目标、进化、反馈。听起来是不是特别像管理人？

## 五、第六个变化：Workflow 越薄，公司越强

Kavak 原来也做了大量 Multi-Agent Workflow Graph，而且已经跑起来了。结果更强的模型出来以后，他们发现：**过去精心设计的 Workflow，反而开始限制智能。**

新思路越来越简单：给 Agent 一个虚拟机、Memory、Evolve、公司的 API 和工具，再给一个长期目标，让它自己想办法。

因为过去模型不够聪明，所以我们必须告诉 AI 第一步干什么、第二步干什么；但模型越聪明，你写得越死，它反而越笨。

> **模型越聪明，Workflow 可能越薄。未来重要的不是你替 AI 设计了多少步骤，而是你能不能给它正确的目标、足够的上下文、真实的工具、清晰的权限，以及持续反馈。**

这套系统的服务流是薄的：

**消息进来 → 记忆更新 → 草稿生成 → 红线校验 → 人确认 → 回读核验 → 数据回流**

它没有把每一句话写死，而是把“环境”搭好：客户记忆、健康知识、风险规则、话术、技能、沙盒、评测、审计、权限。

再往前走，就是 **Self-Improving Organization**：

一个客户反馈进来 → Agent 发现问题 → Evals 捕捉问题 → 知识/规则/话术更新 → 沙盒验证 → 第二天所有群一起生效 → 业务结果继续回流。

这时候被训练的，已经不只是模型，**被训练的是整家公司**。

过去一个公司变聪明，是因为员工慢慢积累经验；未来一个公司变聪明，可能是因为**一次经验可以瞬间同步给整个组织**。

所以 AI 带来的终极变化，也许根本不是少招几个人，而是：**公司第一次开始像软件一样可以持续升级。**

## 六、这如何重写一家健康管理公司

当智能可以被无限复制，今天这套公司结构就要重写：

| 旧结构 | 新结构 |
|---|---|
| 顾问—主管—老板的金字塔 | 少量 Agent 运营者 + 少量例外处理者 + 线下服务者 |
| 老板管人头、管考勤、管抽检 | 老板定目标、定权限、看结果、看异常 |
| 公司的资产是客户名单和顾问经验 | 公司的资产是客户记忆、服务证据、纠偏数据和 Agent 能力 |
| 增长靠招聘 | 增长靠 Agent 覆盖率和学习速度 |
| 质量靠主管肉眼 | 质量靠全量核验、红线、审计和 Evals |

老板的角色也变了：**从“管人”变成“设计 Agent 的环境和目标”**。这不是把老板架空，而是把老板从“盯人”里解放出来，去做只有人能做的判断：服务谁、不服务谁、什么价值不能让步。

## 七、谈价时，按什么锚定

不要按“账号数、坐席数、功能清单”谈，那会把操作系统卖成软件。按这五笔账谈：

1. **人力杠杆**：同样几个群，Agent 承担初稿、记忆、跟进、核验、报表，人均可服务群数上升。
2. **产能解耦**：增长不再线性依赖招聘，边际服务成本下降。
3. **风险折价**：红线、留痕、证据链、审计，降低合规与客诉成本。
4. **资产沉淀**：客户记忆、话术、规则、核验数据留在公司，不随顾问流失。
5. **数据护城河**：别人卖“会聊天的 AI”，你卖“可核验的服务闭环”；没有回读核验和人工纠偏数据，竞品抄不走。

**定价锚点：你少招几个督导、多接几个群、少赔几单投诉、少流失几个客户。** 价格应该锚定经营增量，而不是我的工时。

如果谈的是你个人的价，锚点同样不是工时，而是：**你交付的是这家公司的操作系统和增长方式，不是一个外包项目。**

## 八、可以直接对老板说的五句话

- “你买的不是一套客服工具，是把公司从‘人头生意’改成‘系统生意’的操作系统。”
- “过去增长靠招人，现在增长靠 Agent 覆盖；人可以更少，但每个群的服务更稳。”
- “AI 真正复制的不是普通员工，是你最优秀的顾问的判断；而且一次纠偏，所有群都能学会。”
- “这套东西最难的不是模型，是闭环：发出去能回读、能核验、能追责、能沉淀。竞品抄得走界面，抄不走你的数据和纠偏记录。”
- “价格不该按功能算，该按你少招几个督导、多接几个群、少赔几单投诉来算。先在一个团队跑出基线，再按增量利润谈。”

## 九、别说过头的边界

这套话术要经得起追问，以下三条建议主动说清楚：

1. **目前是 P1，不是全线跑通。** 工作台、患者、群、顾问、服务流、告警、账号、审计、安全已接真实数据；知识库、风险规则、话术库、技能市场、企微接入状态、AI 模型、开通服务、数据报表尚未接真实后端，界面明确显示“未接入”。
2. **“AI 决定经营”目前是“AI 提供全量事实、生成服务动作、量化人的执行”**，不是“AI 自动决定组织、定价、客户取舍”。把边界说清楚，比说满更有杀伤力。
3. **不自动发群。** 医疗健康的信任边界必须由人确认；Agent 拥有任务，人是在不可逆节点被调用的能力。自动全量学习、自我进化是路线图，不是已验收。

---

真正能打动对方的，不是“AI 什么都能决定”，而是：

> **这家公司第一次能全量看清自己是怎么服务的，并且每一条服务都能被核验、被追责、被复用。谁掌握了这个闭环，谁就掌握了定价权。**
