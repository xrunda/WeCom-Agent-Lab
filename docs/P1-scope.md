## 0. 一句话

**每位患者一个专属健康 Agent。它记得患者的一切，主动替患者想事、办事，说出口之前由顾问把关。**

底座是 **DSH（DeepSeek Harness）**，所有业务能力都以 DSH 插件的形式实现。外面套一个面向健康管理行业的**通用 Web 控制台**。七通无创以第一个租户的身份登录体验。
P1 的目标是「看上去完整、核心是真的」，签单后再按金额决定深度和定制范围。

**对外叙事**：一人一 Agent，长期记得你。Agent 提议，顾问把关，系统核验确实送达。

> 「Agent 不直接对患者说话」是平台硬约束（F1：机器人进不了外部客户群），我们把它讲成卖点：健康领域的 AI 不经人审核就直接对患者说话，本身就是合规风险。将来有了患者端渠道（小程序、服务号，那里没有 F1 限制），Agent 才直连患者，这一步放进三期路线。

## 3. 架构

```text
企微 ──存档 SDK──┐                          ┌── 顾问企微（机器人 1:1：卡片 + 正文）
                 ▼                          │
┌──────────────── DSH Host（单实例，腾讯云 Ubuntu VM）───────────────┐
│ zhiban-wecom     企微通道：C2 移植（存档轮询 / 机器人 / 串行队列 / 回读核验）│
│ zhiban-patient   群 ↔ 患者 ↔ 会话路由；isServiceable 判定            │
│ zhiban-memory    长期记忆：工具 + 每轮注入 + 可查可改可删            │
│ zhiban-care      主动计划：基于 DSH schedule                         │
│ zhiban-guard     红线门禁：agent/pre-step + 输出后校验 + 风险等级    │
│ zhiban-knowledge 知识库：skill + 资源文件 + 命中统计                 │
│ zhiban-console   控制台 API：登录、租户设置、REST、SSE、审计         │
│ DSH 原生：会话持久化 / 压缩 / schedule / storage-sqlite / 模型设置    │
└───────────────────────────────▲─────────────────────────────────────┘
                                │ HTTPS（插件注册的路由）
                       知伴控制台（React SPA，七通登录这里）
```

**核心约定**：

- **一位患者 = 一个 DSH 工作区 + 一条长期会话**。这条会话就是这位患者的 Agent。
- **客户消息 → Agent 回合**：`zhiban-wecom` 读到服务群里的客户消息后，由 `zhiban-patient` 找到对应的患者会话，把消息注入并触发一轮。Agent **必须**调用 `reply_draft` 工具产出草稿（不是靠最终文本回复），C2 收到草稿后推给顾问。
- **核验结果回写**：已核验、改后发送、发错群、未核验这些结果作为系统消息写回患者会话，Agent 知道"说出去的话到底送达没有"。
- **主动计划**：Agent 调用 `schedule_create`，或在控制台手动创建；到期后 DSH 把提醒投递进患者会话，触发一轮，产出的草稿标记为「Agent 主动」。
- **七通只碰控制台**，接触不到 DSH 本体。DSH 自带的 Web 界面只给我方内部运维用。P1 是单租户，不需要 dshserver 那套每用户独立运行时（它只兼容 0.1.x）。
- **C2 核心逻辑不改**：`C2Service`、`SerialQueue`、`Verifier`、`ArchiveTrigger` 原样移植，替换的只有三处接缝（交接文档 §6）。

**M0 风险与回退**：如果 DSH 没有公开接口供插件向指定会话注入消息并触发一轮，回退方案是**每条客户消息开一个子任务会话**，由插件把该患者的记忆和最近对话作为上下文带进去，结果仍归到患者名下。对外的「一人一 Agent」概念不受影响，受影响的只有 `zhiban-patient` 的路由实现。

### 4.1 工作台 · A+B
- KPI（A）：在线 Agent 数、今日主动关怀数、今日新增记忆、今日草稿数、核验通过率、平均响应时长、未处理告警
- 趋势图、排行（B）
- 最近服务动态（A）：取实时服务流最近 10 条

### 4.2 患者 Agent · A ★
- 列表是卡片墙：Agent 头像、患者备注名、在线状态、已陪伴天数、记忆条数、待执行计划数、最近一次互动
- **Agent 主页**：
  - **记忆**：分类列出（饮食禁忌、作息、目标、家庭情况……），每条标来源（哪句话抽取的）、时间；可编辑、删除，操作进审计。标语：「患者的记忆，患者做主」
  - **主动计划**：待执行 / 已执行；来源标「Agent 识别」或「手动」；可新建、取消
  - **办事记录**：Agent 调用过的每个工具（草稿、写记忆、建计划、升级人工），带结果
  - **对话时间线**：患者消息、Agent 草稿、实际发出的正文、核验结果
  - 基本信息、标签（A）；健康档案、服务计划（B，示例）

### 4.3 实时服务流 · A ★
- 生命周期：`客户消息 / Agent 主动 → 草稿 → 推送顾问 → 顾问确认 → ✅已核验 / ✏️改后发送 / ⚠️发错群 / ❌未核验`，SSE 实时滚动
- 每行：来源（患者提问 / Agent 主动）、群、患者、摘要、风险、状态、各节点耗时
- 详情抽屉：完整时间线、草稿与实发正文差异高亮、引用的记忆与知识、审计记录
- 图片 / 文件 / 语音消息也显示在流里，标「暂不支持自动草稿」（二期补）

### 4.4 体验中心（沙盒）· A ★
真实链路绑在我方企微主体和顾问席位上，七通的员工无法触发。沙盒用**真 DSH、真模型、真插件**，只把渠道换成模拟的：
- 左栏是模拟客户群，右栏是模拟顾问手机（卡片 + 正文，与真机一致），侧栏是该沙盒患者的**记忆面板**
- 预置引导：「我对海鲜过敏」→ 记忆面板新增一条 →「晚上吃什么」→ 草稿避开海鲜并说明依据
- 四个操作按钮触发四种核验结果：照发 / 改写后发 / 发到别的群 / 只点已发送不真发
- 顶部标「体验沙盒 · 不连接真实客户群」；沙盒数据单独存放，不计入工作台和报表，可一键重置

### 4.5 质检与告警 · A
- 类型：发错群、未核验、超时提醒（15 分钟）、超时升级（60 分钟）、推送死信、顾问被暂停、红线命中
- 操作：标记已处理（填备注）、**释放队列**（解决 G9 永久堵塞）、**恢复顾问**
- 60 分钟升级时，机器人 1:1 推送给配置的主管（解决 G10）

### 4.6 服务群 · A
即 C2-3-01 判定契约的 P1 实现，不用等七通回答那五个问题：
- 存档里出现的、含外部成员（`wm`）的群自动发现，默认「待确认」
- 管理员可切换：**服务中 / 仅采集 / 停用**，只有「服务中」的群会进入 Agent
- 绑定患者（新建或选已有）、改群名、指定顾问
- 不含外部成员的群不进列表，正文不落库、不进日志
- 契约签名 `isServiceable(roomId, senderId)`，P1 只按群判断

### 4.7 顾问 · A+B
- 列表（A）：席位、在线、当前队列、暂停 / 恢复
- 席位与成本（A）：已购席位、到期日、「顾问数 × 单价」估算
- 绩效（B）

### 4.8 知识库 · A
- 分类 + 条目增删改，可启用 / 停用；保存后重新生成 `zhiban-knowledge` 的资源文件，下一轮对话生效
- 命中次数（A，来自草稿引用）
- 不做向量检索和文档导入（二期）

### 4.9 风险规则 · A+B / 话术库 · B
- 风险规则：红线（不诊断、不调药、不承诺疗效、急症只引导就医）和关键词。**关键词规则真实生效**，由 `zhiban-guard` 执行
- 话术库：示例

### 4.10 技能市场 · A+C
- **已启用**（A）：从 DSH 插件清单读取已安装的 zhiban 插件，显示为技能卡（企微服务通道、长期记忆、主动关怀、健康红线、知识问答）
- **即将上线**（C）：餐食图片识别、体检报告解读、预约提醒、智能设备数据（血糖 / 血压）接入、患者端小程序直连
- 页面说明「每项技能都是一个可插拔插件」，这是体现通用平台的关键页

### 4.11 数据报表 · B / 行业方案包 · B/C

- 方案包：「健康调理服务（已启用）」；体重与代谢管理、慢病随访、产后修复、医美术后护理、中医调理为 C

## 5. Agent 行为约定

- **人设**：系统提示词由「Agent 设定」生成，包含名字、称谓、语气，以及红线
- **每轮输入**：本条消息 + 会话历史（DSH 自动管理与压缩）+ 记忆注入 + 知识库 skill
- **每轮必须**以 `reply_draft({ body, inboundSummary, riskLevel, citedMemoryIds, citedKnowledgeIds })` 结束；不需要回复时调用 `reply_skip({ reason })`。没调这两个工具就结束的回合，按降级处理
- **可选动作**：`memory_write`、`memory_update`、`schedule_create`（主动计划）、`escalate_to_human`
- **红线**：`zhiban-guard` 在 pre-step 阶段注入规则，草稿产出后再做关键词校验；命中即标高风险，不阻断推送，由顾问决定发不发
- **降级**：模型超时（15 秒）或出错时，回退到模板草稿，标「模板草稿」并计数
