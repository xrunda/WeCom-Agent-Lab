## 0. 结论先行

### 0.1 目标形态判定

**「外部客户群 + 外部联系人 + 内部员工 + 可交互 AI 机器人」在官方能力上不成立。**

三条可能的机器人路径，全部被官方限制在外部群之外：

| 路径 | 外部客户群 | 官方措辞 | 核验 |
|---|---|---|---|
| 智能机器人（普通模式 / API 模式） | ❌ 不能添加 | 「仅支持添加至企业内部群」「互联群、上下游群、外部群暂不支持添加」 | ✅ |
| 群机器人（已更名「消息推送」，Webhook） | ❌ 不能添加 | 「外部群暂不支持」「外部群聊暂不支持添加『消息推送』」 | ✅ |
| 客户群「自动回复 / 小助理」 | ⚠️ 唯一可用，但非 AI | 客户 @小助理 + 关键词 → 固定话术 | ✅ |

### 0.2 读 / 写能力

| 方向 | 官方唯一路径 | 实时性 | 关键限制 |
|---|---|---|---|
| 读外部群消息 | 会话内容存档 | ❌ 轮询，非推送 | 付费 + 认证 + 盖章确认函 + 员工告知 + 客户同意；仅 5 天内；SDK（非 HTTP） |
| 在外部群发消息 | 企业群发（`add_msg_template`） | ❌ | **成员确认后才发送**；每群每月上限 = 当月天数 |
| 在外部群被动回复 | 小助理关键词 | ✅ | 纯规则、无 AI、无 API 配置、群主逐群开启 |

### 0.3 对 M1 的影响

- 按 PRD §5，**核心通过条件（同群可交互机器人 + 同群自动/主动发送）无法满足**，M1 应判 `FAIL`（官方能力层面），实测阶段用于排除灰度差异与留证。
- **会话存档只能解决“读”，不解决“写”**。PRD §4 第 3 条已明确：无发送路径时，采购存档不能视为闭环。
- 不得以内部群机器人、机器人私聊或顾问人工转发替代外部群验收。

### M1-01 机器人模式

| 字段 | 内容 |
|---|---|
| 平台官方支持 | **YES**（仅单聊与企业内部群） |
| 来源 | E1（2026-11-08）；E10/E11（🔎 待复核） |
| 当前账号权限 | UNKNOWN |
| 测试环境 | 待填 |
| 实测状态 | NOT_TESTED |

**官方能力对比**

| 维度 | 普通模式 | API 模式 |
|---|---|---|
| 开发量 | 0 代码 | 需自建服务 |
| 模型 | 企微内置模型（DeepSeek 系列 / Hunyuan 系列） | 企业自有模型与数据 |
| 知识集 / 插件 / 工作流 | 支持 | **不可用** |
| 主动推送 | **不支持** | 支持 |
| 连接方式 | — | 长连接 `wss://openws.work.weixin.qq.com` 或 URL 回调（二选一） |
| 切换 | 两模式可双向切换 | 同左 |
| 使用数据统计 | 计入 | 不计入 |

**关键判断**：M1 要求“优先使用企微原生智能机器人及内置模型”。若走 API 模式拿主动推送，就会**失去内置模型与知识集**，与 PRD §1.1 冲突；若走普通模式保内置模型，则**没有主动推送**。这是产品层的能力割裂，不是配置问题。

**下一步**：在内部群做对照实验，确认两模式的实际行为（ISSUE M1-B-08）。

### M1-02 外部群接入 ★ 决定项

| 字段 | 内容 |
|---|---|
| 平台官方支持 | **NO** |
| 来源 | E1、E3（2026-11-08 直读官方帮助中心） |
| 当前账号权限 | UNKNOWN |
| 测试环境 | 待填（需外部客户群 + 双端客户端） |
| 实测状态 | NOT_TESTED |

**官方原文**

- 智能机器人：「**仅支持添加至企业内部群**，机器人识别群内 @ 它的消息并回复。」
- 同一页面限制条目：「群聊仅限企业内部群，**外部群、互联群、上下游群均不能添加**。」
- 群机器人 / 消息推送：「**外部群暂不支持**」「**外部群聊暂不支持添加『消息推送』**」。

**外部客户群唯一官方可交互身份：小助理**

| 维度 | 情况 |
|---|---|
| 触发 | 客户在群内 **@小助理**（必须从成员列表选择）+ 关键词 |
| 回复 | 文字、图片、视频、网页、小程序；单条 ≤ 4000 字 |
| 规则 | 每条规则 ≤ 10 个关键词，单关键词 ≤ 32 字；按规则顺序取第一条 |
| 配置 | 仅超级管理员可配；**不支持 API 配置** |
| 生效 | 群主需在每个客户群单独开启；Mac 端暂不支持开启 |
| AI | 无。纯关键词匹配，不接大模型 |
| 差异配置 | 不支持给不同客户群配置不同内容，只能统一开关 |

**阶段 A 判定**：PRD 要求的“外部客户群内可交互 AI 机器人”**平台官方明确不支持**。M1-02 记为 `FAIL`（官方能力），最终状态待阶段 B 实测复核。

**为什么仍要实测**：① 排除灰度/内测/版本差异；② 留证据满足 PRD“成功/失败均留证”；③ 记录“无添加入口”的具体界面与版本号。

### M1-03 实时消息

| 字段 | 内容 |
|---|---|
| 平台官方支持 | **NO**（实时推送）；**PARTIAL**（存档轮询） |
| 来源 | E6、E9 |
| 实测状态 | NOT_TESTED |

- 客户联系接口清单中没有“读取客户群消息”的接口，只有群列表、群详情、入群方式、群发、opengid 转换（E9）。
- 自建应用的回调不包含客户群消息正文；只有群创建/变更/解散类事件。
- 唯一的消息正文来源是会话内容存档，其为 **SDK 拉取（轮询）**，不是回调推送（E6）。
- 可获取字段：`msgid`、`action`、`from`、`tolist`、`roomid`、`msgtime`、`msgtype`（E6）。
- 消息类型覆盖文本、图片、文件、语音、视频、链接、小程序等（E6）。
- 图片/文件经 `sdkfileid` + `GetMediaData` 拉取，单次最大 512K（E6）。

**结论**：可以“近实时”（分钟级轮询），但**不存在真正的事件推送**。

### M1-06 主动发言

| 字段 | 内容 |
|---|---|
| 平台官方支持 | **NO**（程序直接发送）；**PARTIAL**（企业群发） |
| 来源 | E7 |
| 实测状态 | NOT_TESTED |

**官方原文**：「调用该接口并不会直接发送消息给客户/客户群，**需要成员确认后才会执行发送**」。

| 维度 | 限制 |
|---|---|
| 发送身份 | 由成员（群主/跟进人）确认后发出，非机器人 |
| 频率 | 每个客户群每月接收条数上限 = 当月天数；可调整为每周 7 条或每天 1 条 |
| 目标 | `chat_type=group` + `chat_id_list`，一次最多 2000 个群 |
| 终端要求 | 指定群 ID 的能力仅对 4.1.10+ 客户端生效 |
| 内容 | 文本 ≤ 4000 字节；附件 ≤ 9 个（image/link/miniprogram/video/file） |

**结论**：不满足“无 @、无客户即时触发时，按程序向原群发消息”的验收要求。

### M1-08 会话内容存档

| 字段 | 内容 |
|---|---|
| 平台官方支持 | **YES**（覆盖客户群/外部联系人，需购买） |
| 来源 | E5、E6；覆盖范围与价格为第三方口径（⚠️） |
| 当前账号权限 | UNKNOWN |
| 实测状态 | NOT_TESTED |
| 状态 | **BLOCKED（采购决策）** |

**技术与约束（E6 官方直读）**

| 项 | 值 |
|---|---|
| 接入方式 | 官方 SDK（C/Java），**不是 HTTP REST** |
| 流程 | `NewSdk` → `Init` → `GetChatData` → `DecryptData`；媒体 `GetMediaData` |
| 单次拉取 | ≤ 1000 条 |
| 拉取频率 | ≤ 4000 次/分钟 |
| 媒体频率 | ≤ 25000 次/分钟 |
| 记录时间窗 | **≤ 5 天** |
| 媒体单次返回 | ≤ 512 KB |
| 群标识 | `roomid`（单聊为空） |

**开通前置（第三方口径，需后台核实）**

1. 企业主体已完成企微认证。
2. 超级管理员或被授权管理员操作。
3. 上传盖章《企业微信会话内容存档开通确认函》，审核 1–3 个工作日。
4. 员工告知 + 外部联系人同意；客户不同意则不入档。
5. 价格：第三方口径不一（服务版 450 或 900 元/人/年，2026-01 调价说法），**必须以管理后台购买页为准**。

**关键提醒**：会话存档**不赋予发言权限**。即使买了，也解决不了 M1-06。

### M1-11 人工协作

| 字段 | 内容 |
|---|---|
| 平台官方支持 | 内部群 **YES**；外部群 **NO** |
| 来源 | E1、E2 |
| 实测状态 | NOT_TESTED |

- 内部群：v4.1.32+ 支持机器人转人工（“无法回答”或“含特定关键词”），通过推送成员名片转接；关键词 ≤ 20 个；成员创建的机器人不支持转人工。
- 外部群：没有机器人可接管；小助理无转人工能力。
- 人-人层面：员工在客户群内可正常 @ 其他员工，但这属于人工操作，不是平台提供的人工接管机制。
- 结论：M1-11 的“官方人工接管机制”在外部群不成立。
