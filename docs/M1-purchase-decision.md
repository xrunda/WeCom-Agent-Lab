# M1 会话存档采购决策

> 状态：**已采购**（服务版 1 人，有效期至 2027-11-08） ｜ 2026-11-08
> 原则：采购必须解决明确缺口，且不能掩盖「无发言路径」这一更大问题。
>
> **更新（2026-11-08）**：项目已选定 **C2**（人工确认后转发）。存档从「可选读取能力」变成「回读校验与错群发现」的前提，进入采购评估。§4 的「暂不采购」是 M1 阶段结论，不再适用于 C2。

---

## 1. 决策前提

PRD §4 规定，满足以下全部条件后才能建议采购：

| # | 条件 | 当前状态 | 依据 |
|---|---|---|---|
| 1 | 已确认存档可解决明确的读取缺口（群类型、文字、图片、身份、时间范围） | ⏳ 待实测 | 官方文档显示覆盖客户群/外部联系人，需账号确认 |
| 2 | 明确员工与外部联系人所需告知、授权及数据处理要求 | ⏳ 待确认 | 需法务/合规确认告知文本与同意机制 |
| 3 | **独立核实机器人在同一外部群发言的官方路径** | ❌ **已确认不存在** | 智能机器人/群机器人都不能进外部群；群发需成员确认 |
| 4 | 提供费用、试用、最小席位、技术接入要求 | ⏳ 待后台核实 | 第三方报价不一致 |

> **第 3 条不满足**。这意味着即使采购存档，也**无法形成“自动读 + 自动回”的闭环**。采购只能作为“读”的能力补充。

## 4. 建议

**暂不采购，先完成 M1-02 实测。**

理由：

1. M1-02（外部群能否有可交互机器人）是前置条件，若为 FAIL，则“自动群回复”方向不成立，存档无法闭环。
2. 存档只能解决读取，而 PRD 的核心验收同时要求“发”。
3. 若项目方接受“仅读取 + 人工确认发送”的形态，再按需申请试用，用最小范围（1–2 名成员）验证 30 天。

## 6. C2 视角：授权范围与计费口径（待后台核实）

**授权单位是员工账号（席位），不是群。** 一个已授权员工，覆盖他参与的全部会话：

| 问题 | 预期答案 | 置信度 / 待验证 |
|---|---|---|
| 1 个员工在 100 个外部群，是否这 100 个群都能存档？ | 是。群数量不额外计费；席位按员工算 | 高（按席位计费是公开口径） |
| 群聊里只存该员工发的，还是所有人？ | 整群消息（含客户与其他员工） | 中，需 A5 实测确认 |
| 员工不在的群、离职/退群后的群？ | 不在范围；退群后不再新增 | 高 |
| 未授权员工的 1:1 客户会话？ | 不覆盖 | 高 |
| 未授权员工与已授权员工同群？ | 群消息可能随已授权成员的群记录一并获得 | 中，需实测 |
| 外部客户是否需要同意？ | 需要告知/同意；合规责任在企业 | 高 |
| 数据保留多久？ | 平台侧 ≤ 5 天，长期分析必须自己落库 | 高（M1 已核实） |
| 是否实时？ | 否，SDK 轮询 | 高 |
| 计费 | 按席位/年，可能有阶梯价与最低起购量 | 以后台报价为准 |

**对 C2 的含义**：一个顾问负责 100 个群，买 1 个席位理论上就能覆盖这 100 个群的「发送校验 + 错群发现」；但若要做全量客户对话分析，成本主要不在席位，而在消息量、落库与分析。

**向销售确认的 4 个问题**：

1. 最小起购席位与阶梯价（能否只买 1 个）？
2. 外部群是否整群入库，是否包含客户与其他员工的消息？
3. 外部客户的告知/同意由平台提供什么机制？
4. 5 天窗口的具体口径、SDK 拉取频率与 IP 白名单/私钥要求？

### 6.1 服务版 vs 企业版（C2 选型）

| 能力 | 服务版 | 企业版 |
|---|---|---|
| 内部员工会话（单聊/群聊） | ✅ | ✅ |
| 外部联系人 / 客户群（单聊/群聊） | ✅ | ✅ |
| 语音 / 视频通话存档 | ❌（可禁用） | ✅（通话录音，可转写/质检） |
| 适合场景 | 文字客服、私域运营、C2 草稿校验 | 金融/医疗/法律等需要通话留痕与质检 |
| 参考价（第三方口径，2026-01 调价后） | 约 900 元/人/年 | 约 1800 元/人/年 |

**C2 结论：买服务版，1 个席位起步。**

理由：

1. C2 只需要校验员工在客户群**发出的文字**；服务版已覆盖外部单聊/群聊。
2. 企业版相对服务版的增量只有通话存档；C2 不涉及通话。
3. 外部客户拒绝存档时，其发送的消息拿不到，但**员工自己发出的消息仍会存档**，不影响 C2 的「员工是否转发」校验。
4. 现有环境本来就是服务版 1 人（已过期），续费可复用已有的事件回调、公钥与 Secret 配置。

只有以下情况才升级企业版：需要对营养师/顾问的语音、视频通话做录音留痕、转写或质检。

**语音消息 ≠ 语音通话**：

- **语音消息（`msgtype=voice`）**：服务版就支持。存档返回 `sdkfileid`，音频通常是 SILK，需要 `GetMediaData` 拉取 + FFmpeg 转码 + 自建 ASR 才能得到文字。平台不返回转写文本，客户端本地的「语音转文字」也不通过 API 暴露。
- **语音/视频通话（`msgtype=voiptext`）**：企业版才存档（`callduration`、`invitetype`），同样只给音频，转写仍要自己做。
- 外部客户拒绝存档时，其语音与文字都拿不到；员工侧消息仍会存档。

> 价格与版本能力以后台购买页和销售合同为准；第三方报价仅作量级参考（M1 文档已注明口径差异）。
