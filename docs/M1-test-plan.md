## 0. 测试前准备

### 0.1 环境要求

| 项 | 要求 |
|---|---|
| 企业微信主体 | 已认证 |
| 管理员权限 | 超级管理员（或可操作「智能机器人」「客户联系」「会话存档」的分级管理员） |
| 客户端 | Windows/Mac 各 1 台 + iOS/Android 各 1 台（用于确认入口差异） |
| 测试账号 | 内部员工号 ≥ 2（其中 1 个为群主）；外部测试微信号 ≥ 2 |
| 测试群 | 外部客户群 ≥ 2（A 群用于主流程，B 群用于身份映射），内部群 ≥ 1（对照组） |
| 网络 | 一台有公网 IP 的机器（URL 回调模式）或可出网的内网机器（长连接模式） |

### 0.2 录音/截图规范

- 每步操作前后各截一张图，文件名按 [evidence/README.md](../evidence/README.md)。
- 截图前遮挡客户昵称、头像、手机号、二维码。
- 记录客户端版本号（设置 → 关于企业微信）。

### 0.3 安全

- 全程使用测试账号与无敏感内容的文字/图片/文件。
- 不导入客户资料，不采集非测试人员的消息。
- 密钥写入本地 `.env.local`，不入库、不截图、不发聊天。

## 8. 判定规则

| 状态 | 含义 |
|---|---|
| `PASS` | 实测符合该验收项，且有证据 |
| `PARTIAL` | 部分可用或需附加条件（必须写明条件） |
| `BLOCKED` | 因权限/采购/外部依赖无法执行（写明阻塞原因与解除条件） |
| `FAIL` | 官方确认不支持，或实测失败 |
| `NOT_TESTED` | 尚未执行 |
| `UNKNOWN` | 官方能力本身未确认（仅用于调查态，不用于实测结论） |

### M1 核心通过（PRD §5）

- 外部群形态：外部客户 + 内部员工 + 可交互机器人在同一群，或官方明确支持且实测等效的同群机器人身份。
- 读：官方方式读取该外部群测试文字、图片及身份信息。
- 发：官方方式在原外部群自动发送测试回复，并验证主动发言。
- 历史：给出真实可读时间边界，不支持则明确记录。
- 可审计：每项有截图/日志/官方依据。

**任一核心项 FAIL → M1 整体 FAIL，不以内部群或人工转发替代。**
